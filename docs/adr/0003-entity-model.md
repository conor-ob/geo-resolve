# Entity model

Entities are frozen plain objects discriminated by a `kind` field (`country | subdivision | historic-country | territory`), not classes and not a GraphQL-style `__typename`, which would leak a transport convention into the public API. Every Entity has an `id`: the Alpha-2 code for a Country, the Subdivision code for a Subdivision, the Alpha-4 code for a Historic country, and the user-assigned code permissive Sources use for a Territory (ADR-0012). Alpha-4 is needed because ISO reassigns withdrawn Alpha-2 codes (`CS` was Czechoslovakia, then Serbia and Montenegro).

Non-obvious choices:

- **An `id` is unique across all Kinds, without a Kind prefix.** The formats can't collide: two letters for a Country, two letters from the X range ISO never assigns for a Territory, a hyphenated code for a Subdivision, four letters for a Historic country. `within`, Parents, Successors and Same-as links all rely on this, because they name Entities of any Kind by `id` alone. A prefixed `id` (`country:DE`) was rejected: it repeats `kind`, makes callers write `within: "country:US"`, and stops the `id` being the code they store. Any new Kind must keep its `id` format disjoint from these, and `build` fails on an `id` shared by two Entities of any Kinds.

- **Subdivisions have no `type` field yet.** Subdivision type would be descriptive only ("Limburg, province of the Netherlands"); narrowing is done by `kinds` and `within`, and address-form labels ("State" or "Province" for a form field) are out of scope. No permissive Source carries it (ADR-0001), so rather than ship a half-sourced field, it is deferred; adding a field is a minor release (ADR-0006). When it is added, two decisions remain open: the Source, and whether values use ISO's own category names or a vocabulary of our own. The likely Source is a hand-maintained table mapping each Country's Wikidata classes to types. Across 368 (Country, ISO type) pairs, 288 have a Wikidata class that matches exactly; the remaining 79 need curating by hand. That table must be built from Wikidata, ISO's public browsing platform or national sources, never from `iso-codes`.
- **Subdivisions have a Parent** that may be another Subdivision, because ISO nests some (Spanish provinces under autonomous communities).
- **Historic countries list their Successors and are never auto-mapped to one**, because withdrawals are often one-to-many (the Soviet Union `SUHH` → 15 Countries; the Netherlands Antilles `ANHH` → CW, SX, BQ). Successors are ISO's direct replacements, not political successor states, and are Entity `id`s because a Successor can itself be a Historic country: Yugoslavia `YUCS` → Serbia and Montenegro `CSXX` → RS, ME. Wikidata's "political successors" view (Yugoslavia → SI, HR, BA, MK, RS, ME) is a different fact and isn't used. A helper that follows the chain to today's Countries is deferred until callers ask for it.
- **A Historic country's withdrawal date is ISO's date, as an ISO 8601 string of varying precision** (`"1977"`, `"2003-07-23"`), not a `Date`, which would invent precision ISO never published. It is not the date the state was dissolved: ISO withdrew YU in 2003, not 1992.
- **A Historic country's Name is its common short name** ("Yugoslavia", "Soviet Union"). ISO's formal names ("USSR, Union of Soviet Socialist Republics") are Aliases.
- **Former codes of Countries that still exist are Aliases of the current Country** (`ROM` for Romania, which became `ROU` in 2002), not Historic countries. ISO 3166-3 only records withdrawn Countries, but old data still carries these codes. Only changes ISO documented are included, each citing its source.
- **Entities that ISO lists twice stay separate, joined by a Same-as link** (`PR` ↔ `US-PR`), rather than being merged, so each keeps its own codes and Parent. A link joins one Country to one Subdivision that denotes the whole of the same territory, so SJ (split into NO-21 Svalbard and NO-22 Jan Mayen) and BQ (NL-BQ1–3) have none. The Overlay holds each link once, naming both Entities, and `build` writes it on both sides, so a link can't be one-sided. CLDR deprecates most of these Subdivisions because the territory has its own region code (`uspr` for PR), but still lists them in its containment data, from which codes ISO withdrew drop out. `build` therefore treats a deprecated code that containment lists as a Subdivision, linked or not: FR-CP and SH-TA have no Same-as link, because CP and TA are reserved codes rather than Countries, but ISO 3166-2 lists them.
- **Non-ISO codes live under `codes`** (`codes.ioc`, `codes.fifa`) and are named for their actual Code system, never stored under an ISO field name: a Subdivision code suffix is not an Alpha-3 code, and a FIFA code is not an IOC code. A code sits on whichever Entity has the same territory, of any Kind: FIFA's ENG is on the Subdivision GB-ENG, and GB has no FIFA code (ADR-0012). A Code system's political name for an Entity ("Chinese Taipei" for TW) is an Alias of it.
