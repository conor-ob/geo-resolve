# Bundled CLDR Locale packs instead of Intl.DisplayNames

Localisation ships as generated Locale packs (`geo-resolve/locales/<locale>`) rather than relying on the runtime's `Intl.DisplayNames`. `Intl.DisplayNames` costs nothing in bundle size, but it only covers Country names, has no Subdivision names, cannot map a localised name back to an Entity ("Deutschland" → DE), and its output varies between runtimes. A Locale pack serves both directions (display and resolution) from the same data and gives identical results everywhere. `Intl.DisplayNames` may later be offered as an optional display-only fallback.

When resolving, Names and Aliases match in every Locale loaded into the Resolver, because callers often don't know which language an Input is in. A Name in one Locale can equal a different Entity's Name in another. That clash is treated like any other Ambiguous input (ADR-0004): `resolve` returns `null`, and the `locale` option restricts matching to one Locale. Clashes can only come from Locales the caller chose to load, so the default Resolver (English only) never has them.

Coverage is every CLDR locale at "moderate" coverage or above (roughly 100–150 Locales), where names are reliable. CLDR's Subdivision names are thin in many Locales, so missing ones are filled from Wikidata labels. Where each name came from is recorded in a build report, not in the shipped data.

## Which Locales ship

The base set is CLDR's `coverageLevels.txt` at moderate or above (112 Locales in release-49, English included, a few with a script such as `sr-Latn`). CLDR also has hundreds of regional variants that inherit their coverage, most with exactly their parent's territory names, so a regional variant ships only when its flattened Names differ from its parent's (`pt-PT`, `es-419`, `en-GB`, `fr-CA`); the build report lists which did and why. Identifiers are BCP 47 with hyphens (`sr-Latn`, `pt-PT`), as `Intl` uses, not CLDR's underscores, in both subpaths and the `locale` option. A `KnownLocale` literal union of the shipped identifiers is exported as an optional helper outside semver, like `KnownAlpha2`; `locale` itself is typed `string` (ADR-0006).

A Locale whose CLDR release has no Subdivision names (19 of the 112) gets a Subdivision Locale pack only when Wikidata labels name at least 90% of Subdivisions; below that it ships the Country-level pack alone, so a missing subpath says honestly that the Locale can't resolve Subdivisions reliably. Each Locale's coverage is in the build report.

The build report keeps English in full and one summary row per Locale (Names by Source, Subdivision coverage, Aliases kept and dropped, clashes within the Locale, pack sizes), with each Locale's detail in its own file, so the weekly data-update PR stays readable. Localised Names aren't checked against `iso-codes`: its translations are community gettext files, not ISO's, and CLDR is the authority on Names.

## Shape of a Locale pack

- **Packs are split the way Data packs are.** `geo-resolve/locales/<locale>` holds the Names and Aliases of Countries, Territories and Historic countries (a few KB); `geo-resolve/locales/<locale>/subdivisions` holds every Subdivision's (around 100 KB). There is no per-Country Subdivision Locale pack: at 100+ Locales that would be tens of thousands of files. Names in a pack for Entities the Resolver hasn't loaded are ignored.
- **Every pack is self-contained.** Regional variants (`pt-PT`, `en-GB`, `es-419`) ship as their own packs with CLDR's parent-locale inheritance flattened in at build time, so loading `pt-PT` never requires loading `pt`. The duplication costs disk, not bundles.
- **English is built in, not a pack.** Every Resolver has English: an Entity's `name` stays English (the 0.1.0 contract), English Aliases stay with the Data packs, there is no `geo-resolve/locales/en`, and `locale: "en"` narrows matching to English.
- **Packs carry Aliases in their own language**, from Wikidata, filtered as English Aliases are.
- **The pack's shape is internal.** Unlike a Data pack, a Locale pack can't be built by hand; only shipped packs can be passed to `locales`. Opening the shape up is a later minor release, once it has settled.
- **Localised Names are read through the Resolver**, not from the Entity, because Entities are frozen and shared between Resolvers that load different Locales. The `locale` option keeps one meaning on every resolving function (narrow matching); reading a Name is a separate function, `nameOf(entity, { locale })`, which takes an Entity only, never a loose Input or an `id`, so it can't be confused with resolving. The default entry doesn't export it: its Resolver is English-only, so a bound `nameOf` could only ever return `entity.name` or `null`, a trap for anyone passing another Locale. It looks the Name up by the Entity's `id` in the loaded Locale packs, whether or not the Entity's Data pack is loaded: unloaded Entities' Names are ignored for matching only, and `id`s are unique across Kinds (ADR-0003), so the lookup can't return another Entity's Name.
- **A missing or unloaded Name is `null`, never a fallback.** Reading a Name in a Locale that lacks one for that Entity returns `null` rather than silently falling back to English, so gaps stay visible (`?? entity.name` opts in). A Locale that isn't loaded, or doesn't exist, behaves the same way, and as `locale` it matches no Names or Aliases: it never throws, like `within` and `from` (ADR-0004).
- **`locale` matches an identifier exactly.** `locale: "pt"` never matches the `pt-BR` pack; flattening means `pt-BR` already holds the `pt` Names it uses. Codes still match under `locale`, which narrows Names and Aliases only. It takes one Locale; widening it to a list is a later minor release if needed.
- **Subdivision gaps are filled from Wikidata after CLDR's own inheritance**, using the label in the exact language, then the base language (`pt-br`, then `pt`).
- **Aliases cover the same Kinds in every Locale.** Like English, Locale packs carry Aliases for Countries, Territories and Historic countries only, never Subdivisions.
- **A localised Alias is dropped by the English rules** (not name-shaped, a code, or a Historic country's Name), **and also when it equals a different Entity's Name in the same Locale**, since keeping it only turns that Name's match into `null`. Same-as twins are exempt: "Hong Kong" stays an Alias of HK although it is the Name of CN-HK, as it does in English today, where this exemption covers every such case.
- **Normalisation is unchanged.** It strips every combining mark, which can merge distinct words in scripts where marks carry meaning (Devanagari, Thai, Arabic). Any such merge surfaces as an Ambiguous input, never a wrong Entity, so the build report counts clashes within each Locale and the rule is revisited only if the data shows false merges.
